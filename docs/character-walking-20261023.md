# 人物行走卡頓修正（2026-10-23）

使用者回報主角與其他人物行走卡頓。核對實際模型後發現每隻消防靴約40,000頂點、全部剛性綁在同一骨骼；共用角色接入每幀對兩隻靴子執行完整CPU蒙皮頂點掃描。五名角色即每幀重算約400,000頂點，且隱藏、乘車及已移除的小組仍在更新。

## 已調整

- 檢查每個頂點確為單一骨骼、權重1且沒有形變目標後，快取共用幾何外框，每幀只做骨骼矩陣變換。仍每幀更新腳部範圍；非剛性、混合權重或形變模型自動保留原計算，不更動GLB、角色身分與尺寸。
- 外框為保守包覆：靜止腳底與原計算一致，動作中包覆精確頂點，供既有貼地控制使用；它是模型碰撞／腳底代理，不是現地尺寸。
- 隱藏／乘車／已從場景移除的人物不再每幀更新；雲梯借調隊員依新父節點可見性繼續動作。
- 主角依實際位移推動步態，起步與停步漸變，降低上下彈跳，受牆面阻擋時不維持原地跨步；保持原行走／跑步速度與碰撞。
- NPC 起停漸變、轉身使用與幀率無關的平滑插值；跟隨距離加入起停緩衝，減少臨界距離反覆開關；左右手臂交替擺動。
- NPC 狀態文字只有變更時才寫入介面。

## 已驗證

同一台電腦、同一五名實際深藍模型、80幀Node CPU比較（未包含GPU或整個城市渲染）：

| 人物更新 | 原逐頂點掃描 | 修正後 |
| --- | ---: | ---: |
| 平均每幀 | 191.38ms | 1.08ms |
| 中位數 | 162.58ms | 1.03ms |
| 第95百分位 | 433.46ms | 1.53ms |
| 靴子外框平均 | 189.39ms | 0.024ms |

結果不能直接當作瀏覽器FPS。可用 tests/character-motion-benchmark.mjs 比較；加 --native 執行原逐頂點版本，基準不設CI時間門檻。

測試涵蓋四個原始GLB左右腳動作外框包覆、靜止腳底、非剛性回退、隱藏及雲梯借調人物可見性、30／60／120Hz起停、跨正負π轉向與幀率一致性；原角色動畫、瞄子、上下車及雲梯歸隊另做回歸。

## 尚未驗證與待辦

本批瀏覽器完整三維畫面、使用者電腦實際FPS、長時間任務與實體手機效能尚未驗證。若大場景仍掉幀，下一步需量測GPU渲染、陰影與可見模型數，依證據再處理；本批未降低原人物模型品質、移除既有救災功能或變更地圖比例。
