# 信義街景逐街精修：流程與標準（外牆斑駁、360 度建物、植栽）

> 使用者要求（2026-11-06）：「外牆斑駁感、建物 360 度仿照真實場景建置、草坪與樹木等植栽」規劃為後續建置的流程與標準。
> 本檔是之後每條街精修的共同依據；與 [街道高差與步行規則](street-elevation-walkability-rules.md)、
> [PROJECT-MEMORY.md](../PROJECT-MEMORY.md)「街道植栽」「老舊立面」兩節並用。當次使用者明確指示優先。

## 0. 原則

1. **照片為準，不臆造**：每個外觀、斑駁、植栽決定都要能指回一張照片（或可信圖資）。看不到的面用推定，並標明證據等級（§2.3）。
2. **不拿真實照片當貼圖**：Google 街景／衛星影像只用來判讀分類、顏色、位置，貼圖一律程序產生或用已記錄授權的素材（CC0／MIT／CC BY 需署名）。
3. **不改步行面**：斑駁、外掛物、植栽都是視覺層；任何台階、坡道、花台高差走高差規則，未量測不建。
4. **守效能預算**（§5），手機可跑；新功能都要有開關或遠近細節。
5. **一條街一個 PR**，附紀錄（§6）；使用者說「合併上線」才合併。

## 1. 每條街的作業流程

| 步驟 | 做什麼 | 工具／產出 |
| --- | --- | --- |
| 1 選街 | 依 §7 順序挑下一條；跑清單看未精修量體 | `node scripts/list-street.mjs <路名> 40` |
| 2 取景 | 依 §1.1 取足照片：臨街兩側、路口四向、側巷與後巷、仰角看屋頂 | Google 街景縮圖（只判讀不存檔入庫） |
| 3 對位 | 把照片中的建物對到 LOD1 量體 id（看牆座標、高度、臨路牆長）；注意已有專屬模型的地標（如 `hq-anchor.json` 的消防局） | 同上＋`district-xinyi.json` |
| 4 填表 | 每棟填「精修紀錄表」（§6 範本）：外觀、斑駁等級、四面與屋頂、植栽 | `docs/elevation-reviews/<街>-<日期>.md` |
| 5 寫資料 | 外觀 → `building-overrides-xinyi.json`；綠籬 → `build-hedges.mjs` SEEN；草坪 → `build-lawns.mjs` SEEN；樹木／花台 → §4 對應工具 | 資料檔＋產生腳本 |
| 6 重建 | 有新 variant 或 style 1 → 重建立面構件 GLB；調高快取版本號 | `blender/build_facade_kits.py`、各 `?v=` |
| 7 檢查 | 全部測試；瀏覽器四視角（§6）；Blender 預覽正面＋背面／屋頂 | `tests/*.mjs`、`--only <街名>` |
| 8 紀錄 | README 精修表加一列、PROJECT-MEMORY 必要時補規則 | |
| 9 PR | 說明已完成／待核對／未測試 | `gh pr create` |

### 1.1 取景最低要求

- 臨街：每 30～40 m 一個街景點，左右兩側各一張仰角（pitch −15～−25°）。
- 路口：四向各一張；轉角建物兩個面都要有。
- **側面與背面**：從側巷、後巷、停車場或對街高處取景；拍不到就記「無照片」，依 §2.3 推定。
- **屋頂**：遠處仰角或衛星圖判讀加蓋鐵皮屋、水塔、太陽能板；只判讀有無與概略位置。
- 植栽：每處綠地、綠籬、花台至少一張能看出種類與邊界的照片。

## 2. 360 度建物仿真

### 2.1 四面＋屋頂的內容

| 面 | 台北常見樣貌（老公寓 style 0／住宅大樓 style 1） | 建置方式 |
| --- | --- | --- |
| 臨街正面 | 一樓店面、騎樓、招牌、鐵窗、雨遮、冷氣、外露管線 | 已有：精細立面（`xinyi-shophouse.js`）＋構件（`facade-kits.js`）＋斑駁（`weather()`） |
| 側面（與鄰棟分界） | 多為無窗或少窗的粉刷／磁磚牆，雨痕、補漆色塊、外露管線、冷氣管 | **待建**：簡化立面＋斑駁（§3），無窗則以污漬與管線為主 |
| 背面（後陽台側） | 後陽台加蓋鐵窗、密集冷氣、落水管、熱水器、晾衣 | **待建**：後立面模式（鐵窗陽台＋冷氣＋管線），密度高於正面 |
| 屋頂 | 頂樓加蓋鐵皮屋、水塔、太陽能熱水器、天線、女兒牆 | 已有程序化水塔與加蓋（種子隨機）；**待建**：照片確認者改為逐棟指定 |

### 2.2 資料欄位（新增，於路線圖 P1 實作）

在 `building-overrides-xinyi.json` 每筆精修資料加入（皆選填，未填沿用現狀）：

```json
"weather": 2,
"faces": {
  "side": {"colour": "#b4aea4", "windows": "few", "evidence": "B"},
  "rear": {"kind": "cage-balcony", "evidence": "C"},
  "roof": {"shed": true, "tanks": 2, "solar": false, "evidence": "A"}
}
```

- `weather`：斑駁等級 0～3（§3.1）。
- `faces.side.windows`：`none`／`few`／`regular`。
- `faces.rear.kind`：`cage-balcony`（鐵窗後陽台）／`plain`（一般窗）／`glass`（大樓玻璃）。
- `evidence`：該面的證據等級（§2.3）。

### 2.3 證據等級

| 等級 | 意義 | 紀錄寫法 |
| --- | --- | --- |
| A | 照片直接看到該面 | 「照片確認」＋照片出處 |
| B | 看不到，但由同棟可見面推定（顏色、材質、樓層延續） | 「由正面推定」 |
| C | 看不到，依同類型建物通則（如老公寓背面多為鐵窗後陽台） | 「示意，待核對」 |

測試要檢查：有 `faces` 的面一定有 `evidence`；C 級不得寫成照片確認。

## 3. 外牆斑駁感

### 3.1 斑駁等級

| 等級 | 適用 | 內容 |
| --- | --- | --- |
| 0 新 | 新建大樓、近年翻修 | 無污漬，只有輕微牆腳髒污 |
| 1 輕 | 屋齡約 15～25 年大樓、維護良好公寓 | 窗下淡雨痕、女兒牆下淡污、冷氣滴水點 |
| 2 中（老公寓預設） | 一般老公寓 | 雨痕明顯、牆腳潮濕、鐵窗鏽痕、冷氣滴水、補漆色塊、外露管線 |
| 3 重 | 照片可見嚴重老化 | 再加磁磚脫落／色差補丁、壁癌白華、大片黑垢、多條外露電纜 |

目前 style 0 一律套用約等於等級 2；P2 起依 `weather` 調整強度。等級由照片判讀，沒照片則 style 0 用 2、其他用 1。

### 3.2 斑駁元素與位置規則

| 元素 | 位置規則 | 現有接點 |
| --- | --- | --- |
| 雨痕 | 窗台、冷氣、女兒牆下方往下拉長 | `stainAtlas()`、窗台污漬貼片 |
| 牆腳潮濕 | 一樓牆腳 0.3～0.8 m | 磁磚著色器垂直污垢 |
| 鐵窗鏽痕 | 鐵窗下緣 | `weather()` |
| 冷氣滴水 | 外掛冷氣正下方 | `weather()` |
| 落水管 | 立面兩端或分戶處，到地面 | `pipe()` |
| 黃色瓦斯立管＋錶箱 | 一樓錶箱群往上，每戶分支 | `weather()` |
| 電錶箱 | 一樓近入口 | `weathered-parts.glb` meter |
| 補漆色塊、磁磚色差（等級 3） | 隨機但避開店招 | **待建** |
| 壁癌白華（等級 3） | 牆腳與外露管線旁 | **待建** |

- 位置都是示意；照片能看出實際位置（如瓦斯管在左側）時，在紀錄寫明並調整。
- Blender 端（`blender/taipei_facade.py`、`build_weathered()`）同步同一套規則。

## 4. 植栽

### 4.1 分類與工具

| 類別 | 判讀要點 | 資料／工具 | 狀態 |
| --- | --- | --- | --- |
| 行道樹 | 人行道樹穴、等距 | OSM 樹位（`street-furniture-xinyi.json` trees）＋十二種樹形 | 已有 |
| 照片所見喬木（非 OSM） | 廣場、中庭、退縮綠地的大樹 | **待建**：`scripts/build-trees-seen.mjs` SEEN（種子點＋樹形＋高度示意） | P4 |
| 灌木／綠籬 | 連續低矮葉叢、沿牆或圍籬 | `scripts/build-hedges.mjs` SEEN（沿臨街牆） | 已有 |
| 花台灌木 | 磁磚或石材花台內灌木 | **待建**：沿折線排列模式（官方量體缺臨街牆時也能用，如消防局花台） | P4 |
| 草坪 | 平整低矮草面、可見邊界 | `scripts/build-lawns.mjs` SEEN＋12 m 切塊短草 | 已有 |
| 竹叢、花架、蔓藤綠牆 | 照片可明確辨識 | **待建** | 視需要 |
| 陽台盆栽 | 老公寓陽台、鐵窗內 | **待建**：併入斑駁等級 2～3 的陽台構件（示意） | P2 |
| 店家盆栽 | 一樓門口可移動盆栽 | 不建（可移動物件） | — |

### 4.2 共同規則（摘自 PROJECT-MEMORY「街道植栽」，不重複細節）

- 只做照片確認的植栽，不滿街撒點；分類不確定（草坪 vs 花台 vs 鋪面）就維持平塗並列待核對。
- 保留入口、消防車出入口、樹穴、YouBike、騎樓；不跨車道（距道路中心線＜半路寬＋1.5 m 不放）。
- 草坪邊界沿用 OSM 綠地；樹木、綠籬高度為示意，紀錄寫「示意，未量測」。
- 草坪內有樹、灌木時：樹照 OSM／SEEN 放，草照樣長（不挖洞），但花台、步道須另以綠地多邊形排除。

## 5. 效能預算

| 項目 | 上限 | 位置 |
| --- | --- | --- |
| 立面構件實例 | 70,000 | `facade-kits.js`、`tests/facade-kits.mjs` |
| 綠籬臨街面數 | 每處 ≤24 面 | `tests/street-hedges.mjs` |
| 草坪可見草葉 | 低／中／高 4／10／16 萬 | `LAWN.budget` |
| 側／背面斑駁（P2 新增） | 只在玩家 60 m 內建立、每面構件 ≤ 正面的一半 | 待定，P2 加測試 |
| 照片所見喬木（P4 新增） | 全區 ≤ 300 株，共用實例 | 待定，P4 加測試 |

超過預算先降遠處細節，不刪照片確認的內容。

## 6. 紀錄與驗收

- 每條街一份紀錄，用 [精修紀錄範本](templates/street-refinement-review.md)（含高差檢查欄位，取代只寫高差的範本）。
- 瀏覽器驗收四視角：臨街兩側、一個側面或後巷、近看一棟老公寓（斑駁）、植栽處（草／綠籬）；主控台無錯誤。
- Blender 預覽：每條街至少正面一張；做了背面／屋頂的另加一張。
- 寫明「未測試：實體手機幀率」，直到有實機量測。

## 7. 後續建置路線圖

每階段一個 PR，完成後使用者確認再進下一階段。

| 階段 | 內容 | 完成條件 |
| --- | --- | --- |
| P1 資料欄位 | overrides 加 `weather`、`faces`；測試檢查證據等級；README 欄位說明 | 測試通過，現有外觀不變 |
| P2 側面與背面 | 非臨街牆的簡化立面：側牆污漬＋管線、背面鐵窗後陽台＋冷氣＋陽台盆栽；依 `weather` 調強度；Blender 同步 | 選一條已精修街（建議永吉路30巷）示範，四視角與幀率可接受 |
| P3 屋頂 | `faces.roof` 照片確認者逐棟指定加蓋鐵皮屋、水塔、太陽能；未指定沿用程序化 | 示範街屋頂與照片一致 |
| P4 植栽補齊 | 照片所見喬木 SEEN、花台折線排列（補消防局花台）、竹叢等 | 已有綠籬／草坪不變，新增處有照片出處 |
| P5 回補 | 依街序回補已精修的街段（目前 24 筆）：補 `weather`、`faces`、植栽 | 每街一 PR，用本標準紀錄 |

之後新街（如信義路五段、莊敬路剩餘段）直接用全套流程。
